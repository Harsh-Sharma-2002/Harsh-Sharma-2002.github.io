Overview

Agent Harness is a multi-agent orchestration platform built from scratch with LangGraph, FastAPI, and Streamlit. A Base Orchestrator routes incoming requests to specialized agents, each running through its own isolated, private execution graph rather than a single shared reasoning chain. Originally built as a personal project, it is now also used as the hands-on teaching tool for ASU's Semantic Web Mining course, where it introduces students to agentic system design, LangGraph orchestration, and observability.

Core Capabilities

  • Base Orchestrator routing requests to specialized agents
  • Isolated, private execution graphs per agent
  • Text2SQL agent with bounded schema discovery
  • Deterministic SQL safety validation before execution
  • Structured Pydantic outputs across agent boundaries
  • Full tracing and observability via LangSmith

Text2SQL Agent

The Text2SQL agent turns natural-language questions into SQL through a bounded, multi-loop reasoning process:

  1. Bounded schema discovery, scoped to the relevant tables
  2. Iterative query drafting with multi-loop reasoning
  3. Deterministic safety validation before any query runs
  4. Structured Pydantic output for downstream consumption
  5. Full trace capture through LangSmith for debugging and review

Deployment

The system is containerized end to end with Docker Compose across five services: a Postgres database, an Ollama model server, a one-shot "ollama-init" container that pulls the model and exits, the FastAPI backend, and the Streamlit UI, wired together with explicit health and completion-based dependencies so the stack comes up in the right order every time.

  • Postgres database service
  • Ollama model server
  • One-shot Ollama model-pull init container
  • FastAPI backend, starting only once its dependencies are healthy
  • Streamlit UI, starting once the API is healthy

Cross-platform setup scripts make the whole stack reproducible on a new machine with a single command.

Why This Project Matters

Agent Harness treats multi-agent systems as engineered software rather than a single sprawling prompt. It explicitly addresses:

  • Isolating agent reasoning so one agent's context never leaks into another's
  • Bounding schema discovery and query generation for safety and cost
  • Structured, machine-readable outputs across agent boundaries
  • Full observability into every reasoning step, not just the final answer
  • Reproducible, containerized deployment for real use, not just a demo

It is also the platform I use to teach these ideas directly, as the hands-on tool for ASU's Semantic Web Mining course.
